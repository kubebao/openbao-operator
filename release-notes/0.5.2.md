OpenBao Operator 0.5.2 fixes scheduled backup initialization, PVC admission,
OpenBao Service endpoints, and restore executor safety. It also adds trusted
PROXY protocol source configuration and updates security and release tooling.

### Fixes

In 0.5.1, clusters without `status.backup.nextScheduledBackup` calculate a future
deadline on each reconcile but do not persist it. Scheduled backups can remain
idle indefinitely. Clusters with a persisted deadline can continue to run backups.

The backup manager now persists the first deadline before it waits, observes an
active Job, or returns because backup execution is blocked. A failed status write
returns an error for retry. Initialization preserves an existing deadline and
backup history from the current API object.

After upgrading, check that `status.backup.nextScheduledBackup` is populated.
Verify a completed scheduled backup through `status.backup.lastBackupTime` and
`status.backup.lastBackupName`. A deadline alone does not prove that a snapshot
has reached object storage.

The release also includes these fixes from main:

- Accept narrowly scoped PVC binding updates from the AKS control plane and
  CSI leak-protection finalizer updates from storage provisioners.
- Exclude helper Job Pods from OpenBao API, headless, metrics, read-replica,
  and ACME Service endpoints.
- Stage restore snapshots on disk before submission, with an 8 GiB snapshot
  limit and a 30-minute preparation deadline. Disable executor restarts and
  destructive request redirects or body replay.
- Configure trusted PROXY protocol source IP addresses and CIDRs with
  `spec.configuration.listener.proxyProtocolAuthorizedAddrs`.
- Update Go to 1.27.2, `golang.org/x/net` to 0.60.0, and release-please's
  vulnerable dependencies. Retain the 0.5 cloud storage SDK versions.
- Repair artifact lookup, historical attestation discovery, documentation
  navigation, and local Staticcheck compatibility.

### Upgrade from 0.5.1

Finish active backups, restores, and OpenBao upgrades before updating the
operator. Apply the release CRDs and admission policies before upgrading the
Helm release. The PROXY protocol correction adds a CRD field and admission
validation.

Replace `proxyProtocolBehavior: allow_any` with `allow_authorized` and a
nonempty `proxyProtocolAuthorizedAddrs` list. OpenBao does not support
`allow_any`; the operator now reports that configuration error before starting
the workload. `deny_unauthorized` also requires the address list. Include the
source addresses of operator clients and health probes when using that mode.

Restore executor Jobs require 9140 MiB of ephemeral storage. Check node
capacity before submitting a restore. Snapshots larger than 8 GiB fail before
submission. A failed executor does not retry the destructive operation.

New 0.5.2 manager images, helper images, and charts use the KubeBao GHCR namespace.
With Helm `--reuse-values`, set `image.repository` to `ghcr.io/kubebao/openbao-operator`,
set `image.tag` and `operatorVersion` to `0.5.2`, and clear or replace an older
`image.digest` pin. Update any helper image overrides to matching 0.5.2 images.
Use verified mirrored references when a private registry supplies the images. Historical
0.5.1 artifacts retain their `dc-tec` publisher identity. Verify signatures and
attestations against the publisher of the selected release.

### Upgrade from 0.5.0

Follow the 0.5.1 migration guidance before applying the 0.5.2 CRDs and admission
policies. The release retains the 0.5.0 API wire format. The operator upgrade
harness checks runtime upgrades from 0.5.1 and preserves the historical 0.5.0
API migration fixture.
