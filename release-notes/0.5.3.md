OpenBao Operator 0.5.3 rebuilds the manager and helper images with Go 1.27.3
to address CVE-2026-111943, the eMudhra intermediate CA compromise.

### Security

Go 1.27.3 rejects certificate chains containing any of the eight compromised
public keys. This protects TLS clients that trust public certificate authorities,
including object storage clients and OpenBao clients configured for public ACME.
Supplying a custom storage CA does not remove this exposure in older operator
images because storage clients add that CA to the system trust pool.

The release updates the manager, init, backup, and upgrade images. It does not
change the API, CRDs, admission policies, or RBAC. It does not rebuild or update
the separate OpenBao server image or other external clients.

Read the [Go security advisory](https://github.com/golang/go/issues/82345) and
[Mozilla incident report](https://blog.mozilla.org/security/2026/10/20/protecting-firefox-users-following-the-compromise-of-emudhra-intermediate-certificates/).

### Upgrade from 0.5.2

Finish active backups, restores, and OpenBao upgrades before updating the
operator. Upgrade the chart, manager, and helper images to 0.5.3. With Helm
`--reuse-values`, set `image.tag` and `operatorVersion` to `0.5.3`, and clear or
replace an older `image.digest` pin. Update any helper image overrides to the
matching 0.5.3 images. Use verified mirrored references when a private registry
supplies the images.

Verify the init image of every managed OpenBao Pod after upgrading the manager.
Existing Pods retain helper binaries installed by their old init container until
those Pods are replaced. A successful Helm `--wait` does not prove that this
replacement is complete. BlueGreen voter StatefulSets use `OnDelete`, so a
template update or `spec.runtime.restartAt` change alone does not replace them.

If any Pod retains an old init image, use the
[planned maintenance authorization procedure](https://docs.kubebao.org/docs/operate/maintenance/)
to replace those Pods one at a time. Preserve Raft quorum. Wait for each
replacement to become Ready and verify cluster health before replacing the next
Pod. Disable maintenance mode when the replacements are complete. New backup
and upgrade Jobs must also use the matching helper images.

Certificates that chain through the compromised intermediates fail verification
after this update. Replace affected certificates with certificates from an
unaffected CA. Do not disable TLS verification to restore connectivity.

The operator upgrade harness checks runtime upgrades from 0.5.2. The release
retains the historical 0.5.0 API migration fixture.

### Upgrade from 0.5.1

Follow the [0.5.2 upgrade guidance](https://github.com/kubebao/openbao-operator/releases/tag/0.5.2)
before applying the 0.5.3 CRDs and admission policies. That guidance covers the
PROXY protocol configuration correction, restore storage requirements, and
KubeBao image coordinates.

### Upgrade from 0.5.0

Follow the [0.5.1 migration guidance](https://github.com/kubebao/openbao-operator/releases/tag/0.5.1)
and the 0.5.2 upgrade guidance before upgrading to 0.5.3. The release retains
the 0.5.0 API wire format.
