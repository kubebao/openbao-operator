# OpenBao Operator 0.6.2

OpenBao Operator 0.6.2 adds a configurable startup probe budget for OpenBao databases that need longer to open. It also updates the operator and helper builds to Go 1.27.4 and includes release-publication fixes.

## Allow longer database startup

Set `spec.probes.startup.failureThreshold` to extend the startup window:

```yaml
spec:
  probes:
    startup:
      failureThreshold: 180
```

The default remains 60 failures, approximately five minutes. The example allows approximately 15 minutes. Supported values range from 60 to 720, approximately one hour. Database size alone does not predict startup time; rehearse a cold start with representative data and storage.

The setting applies to voters and read replicas. Extended budgets also increase the rolling-upgrade readiness deadline and fresh-restore deadlines. Fresh restores and scheduled restore tests accept the same `probes` block in their `clusterTemplate`. Readiness and liveness probe settings remain unchanged.

## Upgrade from 0.6.1

1. Finish active lifecycle operations. Verify a recent backup, a rehearsed restore path, administrator access, and seal recovery material.
2. For clusters that need a longer startup window, pause reconciliation and wait for the operator to observe the pause before upgrading.
3. Apply the 0.6.2 CRDs with server-side apply before upgrading the chart:

   ```bash
   kubectl apply --server-side -f \
     https://github.com/kubebao/openbao-operator/releases/download/0.6.2/crds.yaml
   ```

4. Upgrade the matching chart, admission policies, RBAC, operator, and helper defaults together. Review retained image pins and helper-image overrides.
5. While affected clusters remain paused, configure their longer startup budget. Resume reconciliation during a maintenance window and verify quorum, Pod readiness, and client behavior.

Changing the budget updates the Pod template and can replace Pods. A Pod already in a startup-probe restart loop can prevent the StatefulSet from applying the new template. Confirm that the template contains the longer budget before recreating that Pod through authorized maintenance. Retain its PVC. With a healthy quorum, replace one affected Pod at a time and wait for it to rejoin. Use the no-leader recovery procedure if quorum is unavailable.

## Security and compatibility

The operator and helpers use Go 1.27.4. Install the matching release images to receive the toolchain fixes. This does not change or upgrade the separate OpenBao server image.

The Kubernetes API remains `openbao.org/v1alpha1`. This patch does not perform the API-group migration. We will qualify migration from the published 0.6.2 artifacts to the next 0.7 release candidate and update the migration guide before stable 0.7.0. Do not upgrade an existing 0.6 installation directly with a 0.7 chart or manifests.
